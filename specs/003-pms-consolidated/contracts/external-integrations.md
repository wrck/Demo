## 1. 概述

PMS 作为交付管理体系中枢，与 20 个外部系统建立集成点（FR-167）。集成模式涵盖：

- **REST API**（OAuth2/Token 认证）
- **数据库直连**（SQL Server/MySQL）
- **LDAP/AD**（统一认证）
- **SMTP**（邮件）
- **钉钉开放平台 API**
- **对象存储 API**（冷存储）

## 2. 集成系统详细契约

### 2.1 D365 (Microsoft Dynamics 365)

| 维度 | 说明 |
|------|------|
| **方向** | 双向（出站推送 + 入站回调） |
| **协议** | REST API + OAuth2（Token 带缓存） |
| **认证方式** | OAuth2 Client Credentials Grant；Token 缓存，过期前自动刷新 |
| **数据格式** | JSON |
| **触发时机** | 转包合同执行时推送采购订单与采购收货；合同验收节点回写；采购订单/收货状态回调 |
| **关联 FR** | FR-046、FR-048、FR-107；SC-005（成功率 ≥99%） |
| **失败处理/降级** | 记录失败日志并支持重试（最多 3 次，指数退避）；D365 接口不可用时不阻塞转包业务流程（边缘案例）；VAL-045（OAuth2 + Token 缓存） |

**出站接口**（PMS → D365）：

| 接口 | 方法 | 触发场景 | 载荷要点 |
|------|------|---------|---------|
| 推送采购订单 | `POST /d365/purchase-orders` | 转包审批通过进入合同执行 | 转包编号、设备清单、价格、服务商 |
| 推送采购收货 | `POST /d365/purchase-receipts` | 转包合同执行 | 采购订单号、收货明细 |
| 合同验收节点回写 | `PUT /d365/contracts/{contractNo}/accept-node` | 项目闭环 | 合同号、验收节点、验收时间 |

**入站接口**（D365 → PMS，回调）：

| 接口 | 方法 | 触发场景 | 载荷要点 |
|------|------|---------|---------|
| 采购订单状态回调 | `POST /api/v1/integrations/d365/po-callback` | D365 采购订单状态变更 | 采购订单号、状态 |
| 采购收货状态回调 | `POST /api/v1/integrations/d365/receipt-callback` | D365 收货状态变更 | 收货号、状态 |

**数据格式示例**（推送采购订单）：

```json
{
  "subcontract_no": "SC20260701001",
  "po_lines": [
    { "product_code": "P001", "qty": 10, "price": 1000.00 }
  ],
  "facilitator_code": "F001",
  "currency": "CNY"
}
```

### 2.2 CRM 系统

| 维度 | 说明 |
|------|------|
| **方向** | 双向 |
| **协议** | 数据库直连（SQL Server crmtest_MSCRM） / REST API |
| **认证方式** | 数据库账号密码 / API Token |
| **数据格式** | JSON / SQL |
| **触发时机** | 用户信息双向同步（实时/定时 ≤5 分钟延迟）；发货提醒（工期不足且发货异常时） |
| **关联 FR** | FR-159、FR-119；SC-022（延迟 ≤5 分钟） |
| **失败处理/降级** | 同步冲突时标记 `crm_sync_status=冲突`，等待人工裁定（边缘案例）；同步失败重试 3 次 |

**双向同步接口**：

| 接口 | 方向 | 触发场景 | 载荷要点 |
|------|------|---------|---------|
| CRM → PMS 用户同步 | 入站 | CRM 用户信息变更 | 用户编码、名称、地址、行业、服务等级、所属单位、部门、职位、联系人 |
| PMS → CRM 反向同步 | 出站 | PMS 维护用户信息变更 | 同上，增量字段 |
| 发货提醒推送 | 出站 | 工期不足且发货异常 | 项目号、合同号、发货状态、提醒内容 |
| 发货状态回传 | 入站 | CRM 发货状态更新 | 合同号、发货状态、发货明细 |

**同步冲突处理**：
- 同一用户信息被 PMS 与 CRM 同时修改时，标记冲突并保留两端版本
- 通过 `POST /api/v1/users/{userId}/resolve-crm-conflict` 人工裁定同步方向
- 默认策略：CRM 为客户主数据源，PMS 维护增量优先（除主数据字段）

## 3. 多数据源架构集成（来源: 002）

新系统保留老系统多数据源架构（不可合并为单库），通过注解在运行时动态路由（FR-111~FR-112、SC-010）。

| 数据源标识 | 数据库类型 | 用途 | 集成系统 |
|------------|----------|------|---------|
| dataSourceLocal | MySQL (dppms_d365) | PMS 主库，项目管理域 | - |
| dataSourceSMS | MySQL (dpsms) | SMS 短信系统 | SMS |
| dataSourceD365 | SQL Server (AXDB) | D365 ERP | D365（采购订单/收货/合同验收） |
| dataSourceCRM | SQL Server (crmtest_MSCRM) | CRM 客户关系管理 | CRM |
| dataSourceEHR | MySQL (DP) | EHR 人力资源 | EHR |
| dataSourceSAP | SQL Server (DIPULive) | SAP 财务采购数据 | SAP |
| dataSourceOA | MySQL (v71) | OA 系统数据 | OA |
| dataSourceSSE | MySQL (efrs) | SSE 视图（转包付款） | 转包付款 |
| dataSourceITR | MySQL (dptech) | ITR 工单系统 | ITR |

**约束**：
- 通过注解显式声明数据源，运行时动态路由
- 不可跨数据源事务
- 某一数据源不可用时降级提示而非整体崩溃（边缘案例）

## 4. 集成通用约定

### 4.1 集成点管理（FR-167）

所有集成点通过 `IntegrationPoint` 实体统一管理：

| 字段 | 说明 |
|------|------|
| `integration_name` | 集成名称 |
| `target_system` | 对端系统 |
| `direction` | 方向（出站/入站/双向） |
| `protocol` | 协议 |
| `data_elements` | 数据元（JSON） |
| `trigger_timing` | 触发时机（实时/定时/事件驱动） |
| `auth_method` | 认证方式 |
| `retry_policy` | 重试策略 |
| `fallback_strategy` | 降级策略 |
| `status` | 启用/禁用 |

### 4.2 集成调用日志

所有集成调用记录至 `OperateLog`（log_type=`集成调用日志`），支持查询（FR-076）。

### 4.3 重试与降级通用策略

| 场景 | 重试策略 | 降级策略 |
|------|---------|---------|
| REST API 调用失败 | 最多 3 次，指数退避（1s/2s/4s） | 记录待同步任务，不阻塞主业务 |
| 数据库直连失败 | 最多 3 次，固定间隔 5s | 降级提示，标注数据延迟 |
| OAuth2 Token 失效 | 自动刷新 Token 重试 | 刷新失败转人工 |
| 钉钉推送失败 | 最多 3 次 | 转邮件通知兜底 |
| 邮件发送失败 | 最多 3 次 | 记录日志告警 |

### 4.4 数据同步冲突处理

| 场景 | 处理策略 |
|------|---------|
| CRM 双向同步冲突 | 标记冲突，人工裁定（默认 CRM 为客户主数据源） |
| 新老系统并行同步冲突 | 标记冲突，按灰度切换策略裁定方向 |
| 供应链与 PMS 数据不一致 | 告警，以供应链为真实产品信息源 |
