# Feature Specification: PMS 项目交付页面数据 V2 补充

**Feature Branch**: `004-pms-page-data-v2-supplement`

**Created**: 2026-07-10

**Status**: Draft

**Input**: 基于 V2 版本两个文件（《项目交付页面数据、逻辑、功能.xlsx》含 23 个 sheet/812 个 sharedStrings，及《项目交付页面数据DemoV2.html》含 149368 chars），作为 003-pms-consolidated 的补充。V2 相比 V1（20 sheets/602 strings）新增了客户资产库、工期倒推逻辑、配置 Log 自动读取、物料选择独立页面、移动端推送等内容。

- 本 spec 中标注「**新增**」的条目为 V2 全新引入、003 中未覆盖的能力；标注「**增强**」的条目为 V2 对 003 已有能力进行了明确或扩展。
- 新增内容应整合至 003 的对应章节（User Story / FR / Key Entities）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 客户资产库管理（0.1 页面，全新） (Priority: P1) `[新增]`

服务经理或交付管理人员在项目总体跟踪页面点击某项目的"用户单位"超链接，进入 0.1 用户资产库页面（**非实体，是以客户信息为中心的整合性管理与查询界面**），集中查看该用户单位的完整资产视图：用户单位信息（用户编码/用户名称/用户地址/用户行业/用户服务等级）、用户联系人信息、归属用户项目清单、归属用户设备清单、归属用户服务记录、归属用户故障记录、续保记录等业务过程产生的数据。该页面不存储独立数据，数据来源于各业务模块（用户联系人/项目/设备序列号/ITR/维保等）的实时查询聚合。用户服务等级可在资产库页面中修改，修改后对所有关联项目生效。该页面是客户资产管理的统一入口，支撑从用户维度而非项目维度查看资产全貌。

**Why this priority**: 客户资产库是 V2 新增的核心页面，将原分散在各项目中的用户单位、联系人、设备、服务、故障信息按用户维度聚合，是"以用户为中心"资产管理模式的基础。用户服务等级在资产库中统一定义后，成为所有项目联系人服务等级的数据源，影响项目交付优先级与服务响应标准。

**Independent Test**: 可独立测试——给定一个用户单位，能从项目总体跟踪页面通过用户单位超链接进入资产库页面，查看用户单位信息、联系人信息、归属项目清单、归属设备清单，且修改用户服务等级后在关联项目的联系人服务等级中同步生效。

**Acceptance Scenarios**:

1. **Given** 用户在项目总体跟踪页面的项目具体情况列表中, **When** 点击某项目的"用户单位"字段超链接, **Then** 跳转至 0.1 用户资产库页面,展示该用户单位的资产视图
2. **Given** 用户进入 0.1 用户资产库页面, **When** 查看第一部分用户单位信息, **Then** 展示用户编码、用户名称、用户地址、用户行业（均 PMS 导入）与用户服务等级（PMS 导入、可修改）
3. **Given** 用户进入 0.1 用户资产库页面, **When** 查看第二部分用户联系人信息, **Then** 展示用户联系人姓名、电话、服务等级、部门、职务（来源 2.1 及 PMS 导入）
4. **Given** 用户进入 0.1 用户资产库页面, **When** 查看第三部分归属用户项目清单, **Then** 展示该用户单位下所有项目的项目名称、合同号、办事处、销售、项目阶段（同步项目阶段）、发货状态、所属行业、项目级别、项目类型、服务经理、项目经理、下单代理商、实施方式、用户联系人姓名、电话
5. **Given** 用户进入 0.1 用户资产库页面, **When** 查看第四部分归属用户设备清单, **Then** 展示该用户单位下所有设备的序列号、产品编码、产品名称、安装位置（由 5.2 带入）、出厂软件/conboot/cpld 版本、官网版本、在网软件版本（配置 Log 中获取）、维保时长、维保起止时间、配置 Log
6. **Given** 用户进入 0.1 用户资产库页面, **When** 查看第五部分归属用户服务记录与第六部分归属用户故障记录, **Then** 展示该用户的服务记录与故障记录（模块待完善）
7. **Given** 用户在 0.1 用户资产库页面修改用户服务等级, **When** 保存修改, **Then** 关联项目中用户联系人的服务等级同步更新为资产库中定义的等级

### User Story 2 - 工期倒推与阶段计划时间管理 (Priority: P1) `[新增]`

项目经理在制定施工计划页面，基于工期要求（项目结束时间）与合同验收时间，按工期倒推逻辑自动计算各阶段的"工期建议计划时间"。系统采用三层时间模型：阶段计划时间（项目经理实际填写的计划开始/结束时间）、工期要求时间（工前准备带入的项目结束时间，不可调整）、工期建议计划时间（系统按倒推逻辑自动计算的建议值）。非直签与直签项目的工期建议计划时间计算方式不同。工期紧张时系统给出提醒，并可发起 CRM 发货提醒流程。

**Why this priority**: 工期倒推逻辑是 V2 新增的核心计划管理能力，将原 V1 中仅靠项目经理经验估算的阶段时间，改为系统基于工期要求自动反推建议时间，确保各阶段计划时间的合理性与工期可控性。三层时间模型让管理者可对比"计划 vs 要求 vs 建议"，及时发现工期风险。

**Independent Test**: 可独立测试——给定一个非直签项目的工期要求时间，系统能按倒推逻辑自动计算并展示各阶段的工期建议计划时间；给定工期要求离当前时间不足 3 个月，系统能给出工期紧张提醒。

**Acceptance Scenarios**:

1. **Given** 项目经理进入制定施工计划页面, **When** 查看项目基础信息, **Then** 合同验收时间（PMS 导入）与工期要求（工前准备带入）均为只读不可调整
2. **Given** 一个非直签项目（无初验环节）的工期要求已确定, **When** 系统计算工期建议计划时间, **Then** 按以下倒推逻辑展示建议值：工前准备=硬件实施时间-2周、硬件实施=设备配置时间-2周、设备配置=割接上线时间-1~2个月、割接-上线=工期时间-2周
3. **Given** 一个直签项目（含初验环节）的初验时间已确定, **When** 系统计算割接上线建议计划时间, **Then** 割接-上线=初验时间-3个月-2周
4. **Given** 一个直签项目的工期要求已确定, **When** 系统计算工期建议计划时间, **Then** 按直签项目规则展示建议值，且到货签收、初验、终验为必填项（按合同规定试运行）
5. **Given** 项目经理在施工计划表格中, **When** 查看各阶段行, **Then** 每行展示阶段计划时间（计划开始时间/计划结束时间）、工期要求时间、工期建议计划时间三层时间
6. **Given** 工期要求离当前时间已不足 3 个月, **When** 项目经理填写割接-上线及前序动作时间, **Then** 提示"当前项目工期紧张，请与详细落实好工期计划，并与客户确认！"
7. **Given** 工期要求离当前时间不足 3 个月且发货状态为未发货或部分发货, **When** 系统检测到该状态, **Then** 提示"当前项目工期紧张，请与销售确认发货时间"，并提供是否发起 CRM 发货提醒流程的选项

### User Story 3 - 配置 Log 自动读取与工具集成 (Priority: P2) `[新增]`

实施人员在配置调试页面，通过设置 Log 读取路径，关联/调用配置读取工具，自动读取指定路径下的 Log 文件。系统将 Log 文件中对应序列号的配置信息提取，生成设备 Log 并存入设备序列号的相应位置，在 1.1.1.1 配置 Log 页面形成一条新的记录。同时保留本地上传 Log 文件的方式作为补充。

**Why this priority**: 配置 Log 自动读取是 V2 新增的设备配置自动化能力，将原 V1 中仅靠手动上传 Log 的方式，升级为"设置路径+工具自动读取"的自动化模式，大幅减少人工操作，提升配置数据采集的及时性与完整性。自动读取的配置信息回填至序列号详情，为后续版本对比、部署风险分析提供数据基础。

**Independent Test**: 可独立测试——给定一个 Log 读取路径与对应的 Log 文件，设置路径后系统能自动读取、按序列号解析、在配置 Log 页面生成新记录，并在序列号详情中更新在网版本信息。

**Acceptance Scenarios**:

1. **Given** 实施人员进入配置调试页面, **When** 在"设备 Log 存储位置"设置 Log 读取路径, **Then** 系统自动读取对应路径下的配置 Log 文件
2. **Given** 系统读取到 Log 文件, **When** 关联/调用配置读取工具解析 Log, **Then** 将 Log 文件中对应序列号的配置信息提取，生成设备 Log 存入设备序列号的相应位置
3. **Given** 配置 Log 自动读取并生成完成, **When** 查看 1.1.1.1 配置 Log 页面, **Then** 形成一条新的配置 Log 记录，含 Log 文件、上传人（系统自动带入）、上传时间（系统自动带入）
4. **Given** 实施人员需要手动补充上传, **When** 点击"上传 Log 文件"选择本地 Log 文件, **Then** 本地上传的 Log 文件同样在配置 Log 页面生成记录
5. **Given** 配置 Log 由 5.3 配置调试或 5.4 业务联调产生, **When** 每生成一次 Log, **Then** 记录一条信息，且 Log 文件支持点击下载

### User Story 4 - 物料选择与换货流程独立页面（2.2.1） (Priority: P2) `[新增]`

项目经理在 2.2 工勘、分工界面确认页面，对"发货物料是否符合现场施工环境"选择"否"后，进入 2.2.1 物料选择独立页面（V1 中为弹窗形式，V2 升级为独立页面）。在该页面中，项目经理勾选不符合现场环境的物料，填写不符合项说明，点击"发起换货流程"将相关物料与说明信息推送至 CRM 对应销售处，由销售发起换货。

**Why this priority**: 物料选择独立页面是 V2 对 V1 弹窗形式的升级，独立页面提供更大的操作空间与更完整的信息展示，便于项目经理逐项核对物料并批量发起换货。换货流程推送至 CRM 实现跨系统协同，确保不符合现场环境的物料及时更换，避免影响施工进度。

**Independent Test**: 可独立测试——在工勘页面将发货物料符合性选为"否"后，能进入 2.2.1 物料选择页面，勾选物料、填写说明、发起换货流程并验证 CRM 收到推送。

**Acceptance Scenarios**:

1. **Given** 项目经理在 2.2 工勘页面, **When** 对"发货物料是否符合现场施工环境"选择"否", **Then** 展示"进入物料选择页面"超链接
2. **Given** 项目经理点击超链接进入 2.2.1 物料选择页面, **When** 查看物料列表, **Then** 展示勾选框、序列号、产品编码、产品名称、不符合项说明、换货流程列
3. **Given** 项目经理在物料选择页面, **When** 勾选需要换货的物料并填写不符合项说明（现场环境与物料不适配内容说明）, **Then** 所选物料与说明信息被记录
4. **Given** 物料选择完成, **When** 项目经理点击"发起换货流程", **Then** 将相关物料、说明信息推送至 CRM 对应销售处，由销售发起换货流程

### User Story 5 - 培训与满意度调查移动端推送 (Priority: P2) `[新增]`

交付人员在 6.1 现场培训页面填写培训记录后，推送现场培训记录至用户联系人手机，形成一条现场培训服务评价；在 6.2 满意度调查页面填写完工证明与满意度调查表后，推送满意度调查表至用户联系人手机，形成一条服务评价。客户在移动端填写反馈意见并签字回传后，记录同步至交付件页面。

**Why this priority**: 移动端推送是 V2 新增的客户协同能力，将原 V1 中线下传递培训记录与满意度调查表的方式，升级为"推送至客户手机+移动端填写+签字回传"的数字化闭环模式。客户可随时随地完成评价，提升回传率与数据真实性，形成的现场培训服务评价与服务评价归档至交付件。

**Independent Test**: 可独立测试——给定一条培训记录与一条满意度调查表，能推送至用户联系人手机，客户移动端填写并签字回传后，在交付件页面生成现场培训记录与满意度调查报告。

**Acceptance Scenarios**:

1. **Given** 交付人员在 6.1 现场培训页面填写完成培训记录（工程名称、客户联系人、客户联系电话、培训类型、培训时间、培训工程师、培训内容）, **When** 点击"推送至客户手机", **Then** 现场培训记录推送至用户联系人手机，形成一条现场培训服务评价
2. **Given** 客户在手机端收到现场培训记录, **When** 填写客户意见（培训工程师技术水平及表达能力/培训内容及讲解效果/培训满意度/综合意见）并签字, **Then** 签字回传后现场培训记录同步至交付件页面，可下载
3. **Given** 交付人员在 6.2 满意度调查页面填写完成完工证明与满意度调查表, **When** 点击"推送至客户手机", **Then** 满意度调查表推送至用户联系人手机，形成一条服务评价
4. **Given** 客户在手机端收到满意度调查表, **When** 填写评价（工程质量/产品质量/服务质量多维度评分、是否有意愿再次购买、意见）并签字, **Then** 签字回传后满意度调查报告同步至交付件页面，可下载

### User Story 6 - 项目阶段自动流转机制 (Priority: P2) `[增强]`

系统在项目跟踪页面展示项目阶段，项目阶段由当前阶段自动产生。当已完成上一阶段所有工作和产出时，系统自动将项目进入下一阶段，无需人工手动切换。项目阶段根据项目进度自动更新。导航栏采用 2 级结构：1 级为项目阶段（基本信息、工前准备、制定施工计划、实施方案、实施部署、验收交维），2 级为该阶段具体要做的事项，只有 2 级才是可以点击的，导航栏位于页面左边。

**Why this priority**: 项目阶段自动流转是 V2 对 003 中 FR-025（双层并行模型中"自动推进为主"）的明确与增强。V2 明确了"已完成上一阶段所有工作和产出，则自动进入下一阶段"的具体判定逻辑，减少了人工切换的遗漏与延迟。导航栏 2 级结构的明确（1 级阶段不可点击、2 级事项可点击）规范了页面导航交互。

**Independent Test**: 可独立测试——给定一个项目当前处于某阶段，当该阶段所有工作和产出均完成时，系统自动将项目阶段流转至下一阶段；导航栏中 1 级阶段节点不可点击，2 级事项节点可点击跳转。

**Acceptance Scenarios**:

1. **Given** 项目处于某一阶段且该阶段所有工作和产出已完成, **When** 系统检测到完成状态, **Then** 项目阶段自动流转至下一阶段，无需人工手动切换
2. **Given** 项目处于某一阶段且有未完成的工作或产出, **When** 系统检测到未完成状态, **Then** 项目阶段保持当前阶段不变
3. **Given** 用户进入任意项目详情页面, **When** 查看左侧导航栏, **Then** 导航栏为 2 级结构：1 级为项目阶段（基本信息、工前准备、制定施工计划、实施方案、实施部署、验收交维），2 级为该阶段具体事项
4. **Given** 用户在导航栏中, **When** 点击 1 级项目阶段节点, **Then** 1 级节点不可点击（仅展开/折叠 2 级子项）
5. **Given** 用户在导航栏中, **When** 点击 2 级具体事项节点, **Then** 跳转至对应事项页面
6. **Given** 项目阶段发生流转, **When** 项目总体跟踪页面展示项目阶段, **Then** 项目阶段字段自动更新为最新阶段（根据项目阶段自动更新）

## Requirements *(mandatory)*

### Functional Requirements

> FR 聚焦 V2 相比 V1 的新增功能，编号从 FR-V2-001 开始。标注「**新增**」（003 中未覆盖）或「**增强**」（003 中已有但 V2 明确/扩展）。

#### 客户资产库管理（0.1 页面）

- **FR-V2-001**: 系统 MUST 提供 0.1 用户资产库独立页面，作为客户资产管理的统一入口（**非实体，为整合性查询界面**），通过项目总体跟踪页面的用户单位超链接进入。页面数据来源于各业务模块（用户联系人/项目/设备序列号/ITR/维保等）的实时查询聚合，不存储独立数据。**续保记录由外部系统 MES 维护，本系统仅展示只读** `[新增]`

### Assumptions

- **0.1 用户资产库页面**：用户单位信息由 PMS 导入，用户服务等级可在资产库中修改；归属用户服务记录与故障记录模块待完善，一期可能仅提供框架；**续保记录由外部系统 MES 维护，本系统仅展示只读，不维护不编辑** `[新增]`

- **物料换货流程**：CRM 对应销售可接收换货推送，换货流程在 CRM 中发起 `[新增]`

- **项目阶段自动流转**：各阶段的"所有工作和产出"完成判定标准已在各阶段 FR 中定义（如工前准备需完成联系人/工勘/需求分析等） `[增强]`
- **导航栏 2 级结构**：所有项目详情页面均需有左侧导航栏，1 级阶段不可点击、2 级事项可点击 `[增强]`

### Edge Cases

- **用户单位在资产库中无服务等级定义**：当用户单位在 0.1 资产库中尚未定义服务等级时，关联项目联系人的服务等级如何展示？系统 MUST 提示"该用户单位服务等级未定义"并引导至资产库设置
- **归属用户项目清单中项目阶段不同步**：当资产库中展示的项目阶段与实际项目阶段不一致时，系统 MUST 按同步项目阶段逻辑实时更新
- **工期建议计划时间与当前时间冲突**：当按倒推逻辑计算的某阶段建议时间已早于当前时间时，系统 MUST 标红提示该阶段工期已严重滞后
- **直签项目缺少初验/终验时间**：当直签项目的初验/终验时间未由 PMS 导入时，系统 MUST 提示"直签项目需填写初验/终验时间"
- **配置 Log 读取路径无效**：当设置的 Log 读取路径不存在或无权限访问时，系统 MUST 提示错误并允许重新设置路径
- **配置 Log 文件解析失败**：当配置读取工具无法解析 Log 文件中序列号信息时，系统 MUST 提示失败原因、记录失败日志、保留原始 Log 文件供人工处理；**自动读取失败时回退至手动上传模式，手动上传后仍尝试自动解析，解析失败的字段保留为空待人工填写** `[增强]`
- **物料换货推送至 CRM 失败**：当 CRM 接口不可用导致换货推送失败时，系统 MUST 记录待推送任务并支持重试，不阻塞物料选择操作
- **移动端推送用户联系人手机号缺失**：当用户联系人未维护手机号时，系统 MUST 提示"该联系人无有效手机号"并阻止推送
- **客户长期未回传移动端评价**：当现场培训记录或满意度调查表推送至客户后超过约定时长未回传时，系统 MUST 提供超期提醒
- **项目阶段自动流转条件判定歧义**：当某阶段"所有工作和产出"的完成状态存在歧义（如部分交付件已上传但未审核通过）时，系统 MUST NOT 自动流转并提示未完成项
- **导航栏 1 级节点误点击**：当用户尝试点击 1 级项目阶段节点时，系统 MUST 无响应（不跳转），仅支持展开/折叠 2 级子项
- **团队成员模糊匹配结果为空**：当输入姓名无法匹配到任何 PMS 人员或用户联系人时，系统 MUST 提示"无匹配结果"并支持手动输入
- **搜索框多维度组合无结果**：当多个搜索维度组合查询无结果时，系统 MUST 提示"无匹配项目"并建议放宽搜索条件
- **客户资产库跨角色访问越权**：当项目经理尝试访问非自己负责项目的客户资产库时，系统 MUST 拒绝访问并提示"无权限"；交付管理人员尝试访问非本办事处客户资产时，系统 MUST 拒绝并提示"该客户不在本办事处范围内" `[新增]`
- **MES 系统不可用导致续保记录无法展示**：当外部系统 MES 不可用导致续保记录集成失败时，系统 MUST 提示"续保记录暂不可用（MES 系统不可达）"，其他资产信息正常展示，不阻塞整个客户资产库页面 `[新增]`

### Session 2026-07-10

- **本 spec 的定位**：本 spec 为 003-pms-consolidated 的补充规格，聚焦 V2 版本（《项目交付页面数据、逻辑、功能.xlsx》23 sheets + 《项目交付页面数据DemoV2.html》）相比 V1 版本的新增内容。新增内容应整合至 003 的对应章节：User Story 1（客户资产库）整合至 003 的"用户管理与 CRM 同步"模块；User Story 2（工期倒推）整合至 003 的"制定施工计划与审批"模块；User Story 3（配置 Log 自动读取）整合至 003 的"实施部署"模块；User Story 4（物料选择独立页面）整合至 003 的"工前准备"模块；User Story 5（移动端推送）整合至 003 的"验收交维"模块；User Story 6（项目阶段自动流转）整合至 003 的"项目管理核心生命周期"模块。
- **V2 新增内容的分类**：15 项新增内容中，8 项为全新能力（0.1 资产库页面、工期倒推逻辑、配置 Log 自动读取、物料选择独立页面、培训推送、满意度推送、用户单位超链接、搜索框增强），7 项为对 003 已有能力的明确/增强（用户服务等级由资产库定义、主联系人区分、项目阶段自动流转、导航栏 2 级结构、团队成员可编辑增加其他办事处人员、设备级运行业务描述、配置 Log 页面增强）。
- **归属用户服务记录与故障记录**：V2 中 0.1 用户资产库的第五部分（归属用户服务记录）与第六部分（归属用户故障记录）标注为"模块待完善"，一期可仅提供框架，具体字段与功能在后续迭代中补充。
- **工期倒推逻辑的项目类型区分**：非直签与直签项目的工期建议计划时间计算方式不同。**割接上线时间建议值按项目类型动态裁定**：直签项目（含初验环节）使用"初验时间-3个月-2周"，非直签项目（无初验环节）使用"工期时间-2周"。
- **配置 Log 自动读取的工具集成**：V2 中"关联/调用配置读取工具"的具体工具实现方式（独立工具服务还是内嵌模块）不在本 spec 范围内，属技术实现细节，在 plan 阶段决定。
- **移动端推送的技术通道**：现场培训记录与满意度调查表推送至用户联系人手机的具体技术通道（短信链接/H5/小程序/钉钉）不在本 spec 范围内，属技术实现细节，在 plan 阶段决定。
- Q: 客户资产库是实体还是视图？ → A: 客户资产库不是实体，是以客户信息为中心的整合性管理与查询界面，聚合客户联系人、项目、发货设备明细、服务记录、故障记录、续保记录等业务过程产生的数据。不存储独立数据，数据来源于各业务模块的实时查询聚合。
- Q: 客户资产库访问权限范围？ → A: 按角色+数据权限分级。服务经理全局访问，交付管理人员按办事处访问，项目经理按项目归属访问，其他角色不可访问。
- Q: 工期倒推逻辑双口径如何裁定？ → A: 按项目类型动态裁定。直签项目（含初验环节）使用"初验时间-3个月-2周"，非直签项目（无初验环节）使用"工期时间-2周"。
- Q: 配置 Log 自动读取的降级策略？ → A: 自动+手动并行（实施人员可选其一），自动读取失败时回退手动上传并允许解析失败字段为空待人工填写。
- Q: 续保记录的数据来源？ → A: 由外部系统 MES 维护，本系统仅展示只读，不维护不编辑。
