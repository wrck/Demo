# Feature Specification: 项目交付管理系统（PMS）

**Feature Branch**: `001-project-delivery-mgmt`

**Created**: 2026-07-09

**Status**: Draft

**Input**: User description: "项目实施交付系统的阶段汇报文件，分析总结之后作为输入生成新系统规格文档。基于《项目交付页面数据Demo》V1.1 及配套阶段汇报材料（体系化整改、割接管理平台、技术支援部系统整改方案、服务平台及交付运维汇报、用服业务工作流、项目交付流程、系统落地需求、数据元等）。"

## Clarifications

### Session 2026-07-09

- Q: 工前准备中的"用户"指什么角色？数据来源何处？ → A: 指项目交付环境实际使用设备的最终用户（可能是直签客户或非直签代理商实施的设备使用用户），并非使用本系统的用户；项目实施角度归纳为"客户"；客户基础信息与默认联系人由外部 CRM 带入，在本系统中维护更新。
- Q: 项目阶段（8 阶段）如何推进与回退？ → A: 自动推进为主、关键节点人工触发；系统依据各阶段交付件完成情况自动判定阶段完成，割接上线、验收等关键节点需人工触发；支持受控回退（需审批）。
- Q: 多角色并发编辑同一项目数据的冲突如何处理？ → A: 乐观锁+字段级合并；默认乐观并发，保存时版本不一致则提示冲突字段并支持字段级合并；已提交审核的施工计划/实施方案等文档锁定不可编辑。
- Q: 系统的认证与权限模型是什么？ → A: LDAP/AD 集成统一认证，RBAC 角色权限+数据权限；按"办事处/项目归属"维度过滤数据（如项目经理仅见自己项目，交付管理人员见全局）。
- Q: 交付件/配置 Log/巡检/割接归档/AI 训练数据的保留期限与归档策略？ → A: 分级保留：交付件与配置 Log 随项目归档保留 ≥ 5 年（合同质保与审计需要），巡检报告与割接归档 ≥ 3 年，AI 排障训练数据脱敏后长期保留；超期自动归档至冷存储（对象存储低频访问层）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 项目总体跟踪与进度监控 (Priority: P1)

交付管理人员、服务经理及项目经理登录系统后，进入项目总体跟踪页面，通过阶段统计卡片（全部、未开始、工前准备阶段、编写实施方案、制定施工计划、实施部署、验收交维、超期项目）快速掌握各阶段项目数量分布，点击任意统计卡片可弹出对应阶段的项目列表（含序号、办事处、项目名称、合同号、项目等级、用户单位、项目经理）。页面下方的项目具体情况表展示全部项目明细（办事处、项目名称、合同号、项目级别、用户单位、用户服务等级、项目阶段、项目经理），点击"操作"按钮可进入单个项目的全流程跟踪页面。超期项目的项目阶段文字标红以示提醒。

**Why this priority**: 项目总体跟踪是系统的入口与管控中枢，管理者必须第一时间掌握全局项目分布与超期风险，这是后续所有交付动作的前提，具有最高业务价值。

**Independent Test**: 可通过"登录后查看统计卡片数字与项目列表是否一致、超期项目是否标红、点击操作能否进入项目跟踪页"独立验证，交付"全局进度可视"价值。

**Acceptance Scenarios**:

1. **Given** 系统中存在分属不同阶段的多个项目，**When** 管理者打开项目总体跟踪页面，**Then** 8个阶段统计卡片显示对应项目数量，且数字与实际情况一致。
2. **Given** 管理者处于项目总体跟踪页面，**When** 点击"实施部署"统计卡片，**Then** 弹窗显示当前处于实施部署阶段的全部项目列表，含办事处、项目名称、合同号、项目等级、用户单位、项目经理。
3. **Given** 存在施工阶段超期的项目，**When** 项目阶段在表格中展示，**Then** 该超期项目的项目阶段文字标红，并在项目主页面中单独体现。
4. **Given** 管理者处于项目总体跟踪页面，**When** 点击某项目的"操作"按钮，**Then** 跳转至该项目的 1.1 项目跟踪页面。

### User Story 2 - 项目跟踪与基础信息管理 (Priority: P1)

项目经理进入单个项目的 1.1 项目跟踪页面，通过左侧二级导航（基本信息、工前准备、制定施工计划、实施方案、实施部署、验收交维）切换不同阶段视图。基本信息模块展示项目信息（项目名称、合同号、办事处、销售、项目阶段、发货状态、所属行业、项目级别、项目类型、服务经理、项目经理、下单代理商、实施方式、用户联系人姓名、电话）及产品信息清单（产品编码、产品型号、产品描述、项目数量、发货数量、未发货数量、序列号）。团队成员页面展示项目团队（项目经理、服务经理、销售代表、团队成员、用户）信息。序列号详情页面展示设备序列号及出厂/在网版本信息、维保信息，可下钻至配置 Log 页面查看设备配置时产生的 Log 文件。

**Why this priority**: 项目跟踪页面是单个项目所有交付动作的工作台与数据汇聚点，基础信息、团队、设备清单是后续工勘、实施方案、实施部署的数据基础，属核心 MVP。

**Independent Test**: 可通过"打开某项目跟踪页、核对项目信息字段是否完整、产品清单数量是否正确、序列号详情能否下钻配置 Log"独立验证，交付"单项目信息一体化"价值。

**Acceptance Scenarios**:

1. **Given** 项目已由 PMS 导入基础数据，**When** 项目经理打开 1.1 项目跟踪页面，**Then** 项目信息区展示合同号、办事处、销售、发货状态、所属行业、项目级别（根据逻辑自动判断）、项目类型、服务经理（系统自动指派）、项目经理（手动指派）等字段。
2. **Given** 项目经理处于 1.1 项目跟踪页面，**When** 点击产品信息清单中某产品的"序列号详情"链接，**Then** 跳转至 1.1.1 序列号详情页面，展示序列号、产品编码、产品名称、安装位置、出厂软件/conboot/cpld 版本、官网版本、在网软件/conboot/cpld 版本、受影响技术公告、维保时长与起止时间、续保次数。
3. **Given** 项目经理处于序列号详情页面，**When** 点击"配置 Log"超链接，**Then** 跳转至 1.1.1.1 配置 Log 页面，展示设备配置时自动上传的 Log 文件、上传人、上传时间。
4. **Given** 项目经理进入 1.2 团队成员页面，**When** 查看团队成员表，**Then** 展示项目经理、服务经理、销售代表、团队成员、用户主联系人的姓名、联系方式与备注。

### User Story 3 - 工前准备（客户联系人 / 工勘分工 / 需求分析） (Priority: P1)

项目经理在工前准备阶段录入与管理三类关键信息：(a) 2.1 客户联系人详情（联系人属性、客户联系人姓名、电话、客户单位名称、服务等级、部门、职务，支持编辑、删除、失效，主联系人显示在项目页面中；客户基础信息与默认联系人由外部 CRM 带入，在本系统中维护更新）；(b) 2.2 工勘、分工界面确认（工期要求-项目结束时间、机房供电确认、供电方式、网口类型确认、机柜资源、光纤网线、光模块、原厂光模块、上架加电是否需原厂实施及是否需外包、导轨托盘需求及物料领用/外采、发货物料是否符合现场施工环境及发起换货流程）；(c) 2.3 需求分析（项目背景、项目目标、网络拓扑上传、传输现状多选、流量现状-新建/并发/吞吐、运行业务情况表、IP 资源-管理IP/公网IP、冗余备份要求、本机防护要求、运维管理要求多选、下载工程交底书）。注：本节"客户"指项目交付环境实际使用设备的最终用户（可能是直签客户或非直签代理商实施的设备使用用户），并非使用本系统的用户。

**Why this priority**: 工前准备是制定施工计划与编写实施方案的直接输入，客户联系人、工勘结论、需求分析缺一不可，属交付前置的必备能力。

**Independent Test**: 可通过"完成用户联系人录入、工勘问卷填写、需求分析填写并下载工程交底书"独立验证，交付"交付前置信息齐备"价值。

**Acceptance Scenarios**:

1. **Given** 项目经理进入 2.1 用户联系人页面，**When** 录入联系人姓名、电话、单位、部门、职务并标记为主联系人，**Then** 该主联系人信息显示在项目页面中，其他联系人仅在用户联系人页面展示，且支持编辑/删除/失效操作。
2. **Given** 项目经理进入 2.2 工勘页面并填写项目结束时间，**When** 对"上架加电是否需要原厂实施"选择"是"并进一步判断需要外包，**Then** 展示"发起外包流程"链接；对"是否需要导轨、托盘"选择"是"，**Then** 展示"物料领用""外采"两个链接。
3. **Given** 项目经理进入 2.2 工勘页面，**When** 对"发货物料是否符合现场施工环境"选择"否"，**Then** 展示 1.1.1 序列号详情内容，可从中选择不符合现场施工环境的物料发起换货流程。
4. **Given** 项目经理进入 2.3 需求分析页面，**When** 填写项目背景、项目目标、上传网络拓扑、勾选传输现状（IPv6/分片/MTU/Jumbo/隧道）、填写流量现状与 IP 资源及冗余/防护/运维要求，并填写运行业务情况表，**Then** 可根据发货设备情况自动生成并下载工程交底书。

### User Story 4 - 制定施工计划与审批 (Priority: P2)

项目经理在 3.1 制定施工计划页面查看不可调整的项目基础信息（合同验收时间来自 PMS、工期要求来自工前准备），并制定项目施工计划（到货签收、硬件实施、设备配置、业务联通、割接-上线、初验、终验，其中到货签收/初验/终验在项目类型为直签时需填写）。系统根据工期与当前时间的关系给出提醒：工期不足 3 个月时提示"当前项目工期紧张，请详细落实好工期计划，并与客户确认"；若不足 3 个月且发货状态为未发货/部分发货，提示"请与销售确认发货时间"并提供"发起 CRM 发货提醒"流程。施工阶段超期的项目在项目主页面单独体现并标红。计划填写完成后点击"提交审核"，推送到服务经理钉钉进行审批，仅服务经理可修改计划。

**Why this priority**: 施工计划是实施方案与实施部署排期的依据，但需在基础信息与工前准备完成后进行，优先级次之。

**Independent Test**: 可通过"填写各阶段时间、触发工期紧张提醒、提交审核并验证服务经理收到钉钉审批消息"独立验证，交付"计划可控、超期可视"价值。

**Acceptance Scenarios**:

1. **Given** 项目经理进入 3.1 制定施工计划页面，**When** 查看项目基础信息，**Then** 合同验收时间（PMS 导入）与工期要求（工前准备带入）均为只读不可调整。
2. **Given** 工期要求离当前时间不足 3 个月，**When** 项目经理填写割接-上线及前序动作时间，**Then** 提示"当前项目工期紧张，请详细落实好工期计划，并与客户确认"。
3. **Given** 工期要求离当前时间不足 3 个月且发货状态为未发货/部分发货，**When** 系统检测到该状态，**Then** 提示"当前项目工期紧张，请与销售确认发货时间"并提供"发起 CRM 发货提醒"按钮。
4. **Given** 项目经理完成施工计划填写，**When** 点击"提交审核"，**Then** 推送到服务经理钉钉进行审批，仅服务经理可修改计划。

### User Story 5 - 编写实施方案与审核 (Priority: P2)

项目经理在 4.1 编写实施方案页面生成项目实施方案。支持选择"是否已有客户方案"：若已有可上传方案文件并提交系统判断后自动填充至下方表单（可继续编辑）。实施方案涵盖：1.项目概述（项目背景、项目目标引用工前准备内容，项目团队引用 1.2 团队成员，项目清单引用 1.1 产品信息清单，项目进度计划引用 3.1 施工计划）；2.现网现状分析（现网拓扑图上传、现网资源确认引用工勘信息）；3.总体方案设计（建设后拓扑图-判断与需求分析是否变化、设备部署位置规划、设备接口互联规划、设备 IP 与 VLAN 规划、软件版本，均同步更新到序列号模块）；4.配置脚本（网络/业务模块功能/高可用/全量配置脚本）；5.实施步骤（硬件实施含施工环境检查、产品安装、设备供电规范，软件调试，业务配置引用 2.3 运行业务情况）；6.其他方案（质量保障、风险管控与应急预案、运维交付与售后、项目问题闭环与文档归档，勾选后弹出模板可添加到实施方案）；7.项目培训及资料移交；8.售后服务（400 热线、现场服务、软件更新、网站论坛）。支持保存草稿、生成方案、下载方案，并提交审核（服务经理审核，重大项目提交总部复核）。

**Why this priority**: 实施方案是项目交付的核心交付件，但依赖前序工勘、需求分析、施工计划数据，属承上启下的关键能力。

**Independent Test**: 可通过"填写各章节、引用前序数据、勾选其他方案模板、生成并下载方案、提交审核"独立验证，交付"标准化方案产出"价值。

**Acceptance Scenarios**:

1. **Given** 项目经理进入 4.1 实施方案页面，**When** 选择"已有客户方案"并上传方案文件后点击"提交系统判断"，**Then** 系统自动将内容填充至下方表单，且可继续编辑修改。
2. **Given** 项目经理处于实施方案页面项目概述章节，**When** 查看项目背景、项目目标，**Then** 内容引用工前准备对应模块；项目团队引用 1.2 团队成员表；项目清单引用 1.1 产品信息清单；项目进度计划引用 3.1 施工计划。
3. **Given** 项目经理处于 3. 总体方案设计-设备部署位置规划/接口互联/IP 与 VLAN/软件版本，**When** 填写或在线编辑相关表格，**Then** 相关数据同步更新到 1.1.1 序列号模块中。
4. **Given** 项目经理处于 6. 其他方案，**When** 勾选"质量保障方案/风险管控与应急预案/运维交付与售后服务/项目问题闭环与文档归档"，**Then** 弹出对应模板内容并可修改，点击"添加到实施方案"将其纳入方案正文。
5. **Given** 实施方案已填写完成，**When** 项目经理点击"保存"存为草稿、点击"生成"由系统生成方案、点击"下载"下载方案，并点击"提交审核"，**Then** 流程至服务经理审核（钉钉推送），重大项目提交总部复核。

### User Story 6 - 实施部署（到货签收 / 硬件安装 / 配置调试 / 业务联调 / 割接上线） (Priority: P2)

实施团队在实施部署阶段完成五项工作：(a) 5.1 到货签收：上传到货签收单本地文件；(b) 5.2 硬件安装：记录设备安装位置（序列号、产品名称、安装位置由需求分析自动带入可修改、上传安装照片）；(c) 5.3 配置调试：选择本地 Log 存储路径并上传 Log 文件；(d) 5.4 业务联调：填写连接设备信息（设备名称、IP、登录用户名、密码、登录方式 SSH/Telnet/串口、端口号、波特率）并"一键收集配置信息"，同时维护设备清单（设备型号、序列号、运行业务描述）；(e) 5.5 割接上线：前期流程未完成时"发起流程"按钮失效，完成后可发起割接上线流程。

**Why this priority**: 实施部署是方案落地的执行环节，依赖实施方案与到货状态，属交付执行能力。

**Independent Test**: 可通过"上传到货签收单、记录硬件安装位置与照片、上传配置 Log、一键收集设备配置、发起割接流程"独立验证，交付"实施过程可追溯"价值。

**Acceptance Scenarios**:

1. **Given** 实施人员进入 5.1 到货签收页面，**When** 点击"上传本地文件"上传到货签收单，**Then** 文件上传成功并可在 6.4 交付件页面查看下载。
2. **Given** 实施人员进入 5.2 硬件安装页面，**When** 查看设备清单，**Then** 序列号、产品名称由 PMS 导入，安装位置由需求分析自动带入且可修改，可上传安装照片。
3. **Given** 实施人员进入 5.3 配置调试页面，**When** 选择本地 Log 存储路径并上传 Log 文件，**Then** Log 文件上传成功并可在 1.1.1.1 配置 Log 页面查看（上传人、上传时间系统自动带入）。
4. **Given** 实施人员进入 5.4 业务联调页面，**When** 填写设备连接信息并点击"一键收集配置信息"，**Then** 系统采集设备配置信息，设备清单展示设备型号（PMS 导入）、序列号（PMS 导入）、运行业务描述（手动填写）。

### User Story 8 - 割接管理与割接平台集成 (Priority: P2)

### User Story 9 - 服务平台集成与设备信息自动采集 (Priority: P2)

**Independent Test**: 可通过"创建巡检任务、执行巡检、查看巡检报告是否同步至 PMS、设备信息解析结果是否回填至序列号"独立验证，交付"设备信息自动采集闭环"价值。

4. **Given** 项目交付过程中产生交付件，**When** 通过 PMS 线上操作产生，**Then** 按规范格式自动保存至总部数据中心，随工作流自动存储。

### User Story 10 - AI 排障与知识库管理 (Priority: P3)

系统提供 AI 排障能力（AGENT + 知识库 + 提示词模板），辅助快速诊断与标准化排障。AI 工具集含命令解析、功能配置、日志解析、MIB 解析、API 解析、场景答疑。场景分为咨询类（咨询类型/产品类型/版本号/咨询内容）与故障类（咨询类型/产品类型/版本号/典型问题/咨询内容）。知识库数据基础含产品标准手册、命令行手册、典配手册、日志手册、Mib 节点手册、API 手册、技术公告、已知隐患、FAQ、经典案例、排障经验。系统通过提示模板训练 Skill、产品分类与大模型提问重写提升诊断准确率。排障经验转换模板指导工程师完成知识库建设，公共 KB 含产品典型故障对照表、功能模块与产品对照表、硬件定位处理手册；故障排查模板含故障单号、故障现象、产品架构、触发因素（配置触发/物理操作触发/外部因素-流量变化/拓扑变化）、排查过程。排障过程不能依靠结论逆推，须由上而下（由故障现象至排查结论）的完整过程。

**Why this priority**: AI 排障是运维能力增强，依赖知识库与平台底座，属演进式能力。

**Independent Test**: 可通过"输入故障类场景、AI 工具调用知识库输出诊断与解决方案、验证排障经验转换模板填写"独立验证，交付"AI 辅助快速诊断"价值。

**Acceptance Scenarios**:

1. **Given** 工程师输入故障类场景（产品类型/版本号/典型问题/咨询内容），**When** AI 工具解析大类并调用知识库，**Then** 输出诊断与解决方案，并引用相关手册材料、技术公告、经典案例。
2. **Given** AI 排障产生新的排障经验，**When** 工程师按排障经验转换模板填写（故障单号/现象/产品架构/触发因素/排查过程），**Then** 经验沉淀至知识库形成训练数据。
3. **Given** 知识库需扩充公共 KB，**When** 维护产品典型故障对照表、功能模块与产品对照表、硬件定位处理手册，**Then** 可作为 AI 训练策略减小工具不确定性。
4. **Given** AI 排障工具调用知识库，**When** 通过提示模板训练 Skill 与大模型提问重写，**Then** 提升诊断准确率并支持官网归档。

### User Story 13 - ITR 故障处理与 RMA 联动 (Priority: P3)

**Why this priority**: ITR 故障处理是运维服务执行环节，依赖设备信息与知识库，属服务能力。

**Independent Test**: 可通过"创建问题单、提交解决方案、硬件故障调用 RMA、问题闭环归档"独立验证，交付"故障处理全流程闭环"价值。

**Acceptance Scenarios**:

1. **Given** 客户申报故障，**When** 问题受理并确定级别（一/二/三级），**Then** 符合通报标准的邮件通报，并判断是否升单。
2. **Given** 创建问题单，**When** 录入来电人信息/问题描述/设备信息（客户名称序列号/维保状态/版本信息）/发生时间/问题级别，**Then** 工单关联至 PMS 设备与用户。
3. **Given** 问题排查完成，**When** 提交解决方案（根因/方案/解决问题版本/Bug单号/技术公告编号/产线/原因大小类/官网版本号），**Then** 执行解决方案并判断是否需割接变更。
4. **Given** 解决方案为硬件故障，**When** 直接调用 RMA 流程，**Then** 支持处理进展、闭环能力。
5. **Given** 问题已解决，**When** 关闭工单，**Then** 故障报告归档至 ITR 并关联 PMS，实现全流程闭环。

### User Story 14 - 售前测试首次临时授权自动化 (Priority: P3)

售前测试设备发货后，系统自动获取首次临时授权，实现售前测试首次临时授权自动化，避免人工申请等待。

**Why this priority**: 售前测试授权是售前环节效率提升点，属自动化增强。

**Independent Test**: 可通过"售前测试设备发货后系统自动获取首次临时授权、设备可立即用于测试"独立验证，交付"售前测试零等待授权"价值。

**Acceptance Scenarios**:

1. **Given** 售前测试设备已发货，**When** 系统检测到发货状态，**Then** 自动获取首次临时授权并下发至设备。
2. **Given** 首次临时授权已获取，**When** 设备加电，**Then** 可立即用于售前测试，无需人工申请等待。

### User Story 15 - 跨系统数据集成 (Priority: P2)

系统作为交付管理体系中枢，与外部系统建立 40+ 集成点实现数据流转：(a) PMS 作为项目交付主数据源，向各模块下发项目/产品/序列号信息，并接收割接闭环回写（版本/CPLD/conboot/备件序列号刷新）；(b) CRM 双向同步用户信息与发货提醒；(c) 钉钉推送审批（施工计划/实施方案/割接审批）与任务待办；(d) ITR 同步故障工单与待闭环问题，割接失败可便捷提交问题工单；(e) RMA 流程调用与备件关联（割接需备件自动关联备件申请，割接后完成备件退回闭环）；(f) 服务平台同步巡检报告与设备信息解析结果；(g) 客户资产库提供设备资产数据元（割接携带 PMS 实施信息+客户资产库）；(h) 供应链系统导入出厂真实产品信息与官网版本；(i) 割接管理平台完成割接全流程闭环后刷新 PMS。信息自动同步及回传贯穿交付全流程，闭环总结触发归档。

**Why this priority**: 跨系统集成是消除数据孤岛、实现交付体系化的基础，决定系统作为中枢的可用性。

**Independent Test**: 可通过"触发各集成点并验证数据是否按约定方向与格式同步/回传"独立验证，交付"数据流转贯通"价值。

**Acceptance Scenarios**:

1. **Given** 割接闭环，**When** 系统执行归档，**Then** PMS 刷新版本/CPLD/conboot/备件序列号，ITR 待闭环问题更新，客户资产库同步。
2. **Given** 工期不足且发货状态异常，**When** 触发 CRM 发货提醒，**Then** CRM 收到提醒并回传发货状态更新。
3. **Given** 施工计划/实施方案/割接提交审批，**When** 系统推送钉钉，**Then** 对应审批人收到消息并可审批。
4. **Given** 割接失败，**When** 提交问题工单至 ITR，**Then** ITR 创建问题单并关联割接单与设备。
5. **Given** 割接需备件，**When** 系统识别备件需求，**Then** 自动关联备件申请流程；割接完成后完成备件退回才能闭环。
6. **Given** 服务平台执行巡检与设备信息解析，**When** 结果产出，**Then** 巡检报告与设备信息解析结果同步至 PMS。

### Edge Cases

- 当 PMS 导入的项目数据存在缺失或异常（如发货数量为空、合同号重复）时，系统如何处理与提示？
- 当项目经理在工勘页面选择"上架加电需要原厂实施"但又判断"不需要外包"时，系统是否允许直接进入下一环节？
- 当施工计划提交审核被服务经理驳回时，项目经理如何收到通知并修改重新提交？
- 当割接上线流程发起后实施部署某环节发现需返工时，系统按"受控回退（需审批）"机制回退阶段状态。
- 当设备配置 Log 文件超大或上传中断时，系统支持断点续传与分片上传以保证配置数据完整性。
- 当多角色并发编辑同一项目数据发生版本冲突时，系统按乐观锁机制提示冲突字段并支持字段级合并；已提交审核的文档锁定不可编辑。
- 当满意度调查推送至客户后长期未回传时，系统是否提供超期提醒？
- 当迪普服务平台或 UMC 环境不可达时，巡检与设备信息解析结果如何缓存与重传？
- 当 CRM 双向同步发生冲突（PMS 与 CRM 同一用户信息被同时修改）时，系统如何裁定与提示？
- 当供应链导入的出厂产品信息与 PMS 已有数据不一致时，系统如何处理与告警？
- 当 AI 排障诊断结果错误或知识库缺失对应手册/案例时，系统如何回退至人工排障并标记？
- 当割接等级评定结果存在争议（A/B 类边界）时，是否支持人工调整与备注？
- 当接口对照表对端接口信息缺失时，自动生成的网络拓扑如何标注不完整节点？
- 当割接需备件但备件库存不足时，系统如何阻断割接发起并触发备件申请预警？
- 当 ITR/RMA/客户资产库接口临时不可用时，割接建单携带的原始信息如何降级获取？
- 当售前测试设备发货后首次临时授权下发失败时，系统如何告警与重试？
- 当交付件/配置 Log/巡检报告达到保留期限时，系统如何处理自动归档至冷存储？归档后取回的时效与可用性如何保障？
- 当 AI 排障训练数据含客户敏感信息时，脱敏规则的覆盖范围与合规校验如何执行？

- **FR-051**: 用服系统中"客户" MUST 统一调整为"用户"，按用户维度做资产管理（用户编码/名称/地址/行业/服务等级/所属单位/部门/职位/联系人姓名/电话/邮箱/地址）。
- **FR-052**: 系统 MUST 增加"最终用户"概念，区别下单客户和最终使用用户。
- **FR-053**: 用户信息 MUST 从 CRM 同步至 PMS，PMS 维护的用户信息可反向同步给 CRM。
- **FR-054**: 系统 MUST 通过用服日常工作记录更新和维护用户信息。
- **FR-055**: 系统 MUST 提供客户维度的故障档案、服务档案。
- **FR-056**: ITR 系统 MUST 实现故障处理全流程：问题受理→确定问题级别（一/二/三级，符合通报标准邮件通报）→是否升单（升级二线/研发）→创建问题单→提交解决方案→执行→割接变更→问题是否解决→关闭工单。
- **FR-057**: ITR 问题单 MUST 录入来电人信息、问题描述、设备信息（客户名称/序列号/维保状态/版本信息）、发生时间、影响时长、问题级别，并关联 PMS 设备与用户。
- **FR-058**: ITR 解决方案 MUST 含问题根因、解决方案、解决问题版本、Bug单号、技术公告编号、归属产线、原因大小类、当前官网版本号、是否官网版本、是否转内部跟踪、参考资料、资料来源、是否详细。
- **FR-059**: 当 ITR 解决方案为硬件故障时，系统 MUST 直接调用 RMA 流程，支持处理进展、闭环能力。
- **FR-060**: 故障报告 MUST 归档至 ITR 实现全流程闭环，并关联 PMS 系统。
- **FR-061**: 售前测试设备发货后，系统 MUST 自动获取首次临时授权并下发至设备，实现售前测试首次临时授权自动化。
- **FR-062**: 系统 MUST 作为交付体系中枢与外部系统建立集成：PMS（主数据源与闭环回写）、CRM（用户信息双向同步与发货提醒）、钉钉（审批与任务待办推送）、ITR（故障工单与待闭环问题同步）、RMA（流程调用与备件关联）、服务平台（巡检报告与设备信息解析同步）、客户资产库（设备资产数据元）、供应链（出厂产品信息与官网版本导入）、割接管理平台（割接闭环刷新 PMS）。
- **FR-063**: 割接管理平台 MUST 按割接来源（工程交付/维保主动服务/ITR故障/RMA）与割接类型（友商替换/新建入网/搬迁入网/配置组网变更/补丁升级/版本升级/RMA好件替换）建单启动，携带 PMS 实施信息与客户资产库/RMA流程信息/ITR待闭环问题。
- **FR-064**: 割接管理平台 MUST 依据割接等级评定办法（固定规则自动匹配）评定 A/B 类，发起分级审批（A 类服务经理+二线+研发，B 类服务经理+二线，外部客户割接上传客户审批确认单）。
- **FR-065**: 割接方案 MUST 基于模板库（操作前/中步骤规划及窗口设计、设备验证、业务验证、目标验证、回退规划、割接保障规划）生成，并通过信息分析工具包、配置对比工具、配置翻译工具、脚本制作/验证工具、拓扑生成工具、方案输出工具、业务指标判定工具完成风险确认与配置一致性确认。
- **FR-066**: 割接执行 MUST 自动生成割接准备/割接/割接后/回退操作单及 checklist，执行割接前业务测试、正式割接、割接后业务测试与设备功能验证。
- **FR-067**: 割接后 MUST 采集设备信息（三大日志、版本/热补丁/license 备份、整机配置文件、tech-support 一键收集），执行《机房割接实施承诺书》与 checklist 核验签字后闭环。
- **FR-068**: 割接闭环归档 MUST 含 show tech-support 备份、文档更新《客户技术档案》、PMS 刷新版本/CPLD/conboot 与备件序列号，并推送闭环通知至项目干系人。
- **FR-069**: 项目阶段（未开始/工前准备/制定施工计划/编写实施方案/实施部署/验收交维/超期）推进 MUST 采用"自动推进为主、关键节点人工触发"模式：系统依据各阶段交付件完成情况自动判定阶段完成并推进至下一阶段；割接上线、验收交维等关键节点 MUST 由人工触发发起；阶段回退 MUST 受控（需审批通过后回退）。
- **FR-070**: 多角色并发编辑同一项目数据 MUST 采用乐观锁机制：默认乐观并发，保存时检测版本号；版本不一致时 MUST 提示冲突字段并支持字段级合并；已提交审核的施工计划/实施方案等文档 MUST 锁定不可编辑，直至审核完成或驳回。
- **FR-071**: 系统 MUST 对接企业 LDAP/AD 实现统一认证，用户角色与组织架构数据从 LDAP/AD 同步；钉钉用于审批与任务待办推送（非认证入口）。
- **FR-072**: 系统 MUST 按 RBAC 模型控制功能权限，并按"办事处/项目归属"维度过滤数据权限：项目经理仅见自己负责的项目，实施人员仅见自己参与的项目，交付管理人员见全局，服务经理见所辖项目。
- **FR-073**: 系统 MUST 按分级保留策略管理数据生命周期：交付件与配置 Log 随项目归档保留 ≥ 5 年（合同质保与审计需要），巡检报告与割接归档 ≥ 3 年，AI 排障训练数据脱敏后长期保留；超期数据 MUST 自动归档至冷存储（对象存储低频访问层），并支持按需取回。

### Key Entities *(include if feature involves data)*

- **项目（Project）**: 交付管理核心实体，属性含项目名称、合同号、办事处、销售、项目阶段、发货状态、所属行业、项目级别、项目类型（直签/非直签）、下单代理商、实施方式、用户单位、用户服务等级、工期要求、合同验收时间等。项目级别根据逻辑自动判断，服务经理系统自动指派，项目经理手动指派。项目阶段状态机：未开始→工前准备→制定施工计划→编写实施方案→实施部署→验收交维；采用"自动推进为主、关键节点人工触发"模式（系统依据各阶段交付件完成情况自动推进，割接上线/验收交维需人工触发）；支持受控回退（需审批）；超期项目单独标红体现。
- **产品信息清单（ProductList）**: 项目下产品明细，属性含产品编码、产品型号、产品描述、项目数量、发货数量、未发货数量。
- **设备序列号（DeviceSerial）**: 设备唯一标识，属性含序列号、产品编码、产品名称、安装位置、出厂软件/conboot/cpld 版本、官网版本、在网软件/conboot/cpld 版本、受影响技术公告、维保时长、维保起止时间、续保次数；与配置 Log 一对多。
- **配置Log（ConfigLog）**: 设备配置时自动上传的 Log 文件，属性含 Log 文件、上传人、上传时间，关联设备序列号。
- **团队成员（TeamMember）**: 项目团队角色，含项目经理、服务经理、销售代表、团队成员、用户，属性含角色、姓名、联系方式、备注。
- **用户联系人（UserContact）**: 客户方联系人（指项目交付环境实际使用设备的最终用户，可能是直签客户或非直签代理商实施的设备使用用户），属性含联系人属性（主/其他）、姓名、电话、客户单位名称、服务等级、部门、职务；客户基础信息与默认联系人由外部 CRM 带入，在本系统中维护更新；主联系人关联至项目页面。
- **工勘记录（SiteSurvey）**: 工勘分工确认结果，含工期要求、机房供电、供电方式、网口类型、机柜资源、光纤网线、光模块、原厂光模块、上架加电、外包判断、导轨托盘、发货物料符合性等。
- **需求分析（Requirement）**: 项目需求，含项目背景、目标、网络拓扑、传输现状、流量现状、运行业务情况、IP 资源、冗余备份、本机防护、运维管理要求。
- **施工计划（ConstructionPlan）**: 项目各阶段时间安排，含到货签收、硬件实施、设备配置、业务联通、割接-上线、初验、终验时间，及审核状态。
- **实施方案（ImplementationPlan）**: 项目实施方案文档，含项目概述、现网现状分析、总体方案设计、配置脚本、实施步骤、其他方案、培训、售后服务等章节。
- **交付件（Deliverable）**: 项目交付物电子档，含到货签收单、实施方案、初验报告、终验报告、现场培训记录、满意度调查报告。
- **割接单（CutOverOrder）**: 割接管理平台核心实体，属性含割接来源（工程交付/维保主动服务/ITR故障/RMA）、割接类型（友商替换/新建入网/搬迁入网/配置组网变更/补丁升级/版本升级/RMA好件替换）、割接等级（A/B 类）、割接对象、割接组网、操作影响、割接小组、割接计划、割接方案、操作单（准备/割接/割接后/回退）、checklist、闭环状态。
- **割接资源（CutOverResource）**: 割接所需资源，含人员（操作人/复核人/验证人/割接保障人，姓名电话自动同步可修改）与备件（关联备件申请流程，割接后退回闭环）。
- **巡检任务（InspectionTask）**: 服务平台巡检实体，属性含设备类型、目标IP、场景库、状态、巡检 log、巡检报告；输出同步至 PMS。
- **设备信息增强（DeviceEnhancement）**: 设备序列号的扩展属性，含配置历史、部署风险（单机/单点及冗余部署）、运行业务档案、启用功能、接口对照表、网络拓扑（自动生成）、官网版本/用户在线版本/分支版本、一码通安装地址。
- **用户（User）**: 替代原"客户"概念，属性含用户编码、名称、地址、行业、服务等级、所属单位、部门、职位、联系人（姓名/电话/邮箱/地址）；含最终用户（区别下单客户与最终使用用户）；与 CRM 双向同步。
- **客户档案（CustomerArchive）**: 客户维度档案，含故障档案与服务档案。
- **ITR问题单（ITRTicket）**: 故障处理工单，属性含来电人信息、问题描述、设备信息（客户名称/序列号/维保状态/版本信息）、发生时间、影响时长、问题级别（一/二/三级）、问题根因、解决方案、解决问题版本、Bug单号、技术公告编号、归属产线、原因大小类、当前官网版本号；关联 PMS 设备与用户。
- **RMA工单（RMAOrder）**: 硬件故障处理工单，由 ITR 硬件故障解决方案触发调用，支持处理进展与闭环。
- **技术公告（TechBulletin）**: 技术公告实体，属性含技术公告编码、版本号、适用设备；用于割接已知隐患自动匹配与 ITR 故障关联。
- **AI排障知识库（KnowledgeBase）**: AI 排障数据基础，含产品标准手册、命令行手册、典配手册、日志手册、Mib节点手册、API手册、技术公告、已知隐患、FAQ、经典案例、排障经验；含公共 KB（产品典型故障对照表、功能模块与产品对照表、硬件定位处理手册）。
- **排障经验（TroubleshootingExperience）**: 排障经验转换模板产出，属性含故障单号、故障现象、产品架构、触发因素（配置/物理/外部流量/拓扑）、排查过程；沉淀为训练数据。
- **备件（SparePart）**: 割接与运维备件实体，与割接单关联，含备件申请与退回流程状态。
- **临时授权（TemporaryLicense）**: 售前测试首次临时授权，设备发货后自动获取并下发。
- **跨系统集成点（IntegrationPoint）**: 系统与外部系统的集成关系，含方向（同步/回传/调用/推送）、对端系统（PMS/CRM/钉钉/ITR/RMA/服务平台/客户资产库/供应链/割接管理平台）、数据元与触发时机。

## Assumptions

- 假设系统为 Web 端应用，支持主流浏览器（Chrome/Edge），移动端适配在 v1 范围内可选。
- 假设项目基础数据（项目名称、合同号、办事处、销售、发货状态、所属行业、项目类型、下单代理商、实施方式、产品信息清单、序列号等）由 PMS 系统导入，PMS 接口可用且数据准确。
- 假设服务经理审批与通知通过钉钉推送，企业已开通钉钉集成能力。
- 假设项目级别根据预设逻辑（如合同金额、用户服务等级、行业属性等）自动判断，项目类型（直签/非直签）由 PMS 导入。
- 假设用户单位与服务等级由用户管理模块带入，用户主联系人由用户管理模块导入。
- 假设实施方案其他方案模板（质量保障、风险管控、运维交付、问题闭环）由系统预置，可根据项目实际情况修改。
- 假设设备配置 Log 由设备配置工具在配置时自动上传至系统指定存储路径，无需人工手动上传（5.3 页面除外，5.3 支持手动上传）。
- 假设割接上线流程对接割接管理平台（参见配套《割接管理平台 v3》资料），本系统负责发起流程链接。
- 假设 CRM 发货提醒流程对接 CRM 系统，本系统负责发起提醒。
- 假设满意度调查推送至客户的方式（钉钉/短信/链接）在 v1 中初步规划关联用户信息，具体渠道后续细化。
- 假设用户具备稳定网络环境，可访问 Web 端与钉钉。
- 假设项目角色权限分为：交付管理人员（全局视图）、服务经理（审批/修改计划）、项目经理（执行/填写）、实施人员（实施部署执行）、交付人员（验收交维执行）。
